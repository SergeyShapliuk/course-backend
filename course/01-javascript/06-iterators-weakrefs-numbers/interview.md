# 1.6 Iterators, generators, слабые ссылки, числа — interview

> Вопросы проверяют, понимаете ли вы протоколы, которые стоят за `for…of`, приведением типов, числами и слабыми ссылками, и видите ли последствия на границе сервиса. Схема ответа: **тезис** → **подробно** → **ограничения** → **уточняющие вопросы**. Все фрагменты запущены на Node.js v22.22.2 как файлы `.cjs`.

**Как работать с заданиями.** Ответы спрятаны под раскрывающимися блоками.

1. Прочитайте вопрос или фрагмент кода.
2. Запишите или проговорите ответ: результат **и механизм**.
3. Раскройте эталон и сравните оба пункта.

Вопросы M — Middle, SM — Strong Middle, S — Senior.

## Конспект

- **Iterable** создаёт итератор через `[Symbol.iterator]()`, **итератор** одноразовый: `next()` → `{ value, done }`. Досрочный выход (`break`, исключение, деструктуризация) вызывает `return()` — так закрываются ресурсы.
- **Генератор** приостанавливается на `yield`, работает лениво, `return()` выполняет `finally`. `next(x)` передаёт значение в точку `yield`.
- **`for await`** обрабатывает async iterable последовательно — это backpressure; `break` закрывает поток. `for await` по массиву уже запущенных промисов — ловушка необработанного отклонения.
- **Symbol** уникален, не виден в `Object.keys` и JSON; `Symbol.for` — глобальный реестр. Well-known symbols — протоколы (`iterator`, `toPrimitive`, `hasInstance`, `dispose`).
- **ToPrimitive:** `Symbol.toPrimitive(hint)` или `valueOf` / `toString` по подсказке. **`==`:** `null == undefined`, строка и boolean приводятся к числу, объект — к примитиву, `NaN` не равен ничему.
- **Number — IEEE 754 binary64:** `0.1 + 0.2 !== 0.3`, целые точны до 2⁵³ − 1, `toFixed` округляет двоичное значение. **BigInt** — точные целые, не смешивается с Number, в JSON только через `replacer`. С ES2026 `reviver` видит исходный текст числа (`context.source`), а `JSON.rawJSON` записывает число без кавычек.
- **Деньги** — целые минимальные единицы или десятичное представление; **id `bigint`** — строки на всём пути.
- **Слабые структуры** не удерживают ключи; ключ — объект или незарегистрированный символ. Спецификация не гарантирует ни сборку, ни вызов колбэка FinalizationRegistry. Ресурсы освобождают явно.
- **JSON** теряет `Date` (станет строкой), `Map`, `Set`, `undefined`, прототипы, падает на BigInt. **`structuredClone`** сохраняет `Date`, `Map`, `BigInt`, циклы, но не функции и не классы.

## Вопросы уровня Middle

### M1. Что такое протокол итерации и чем iterable отличается от iterator?

<details>
<summary>Ответ</summary>

**Тезис.** Iterable — объект с методом `[Symbol.iterator]()`, который возвращает **новый** итератор. Итератор — объект с `next()`, который возвращает `{ value, done }`, и опционально `return()` для очистки. `for…of`, spread, деструктуризация, `Array.from`, `Promise.all` работают с любым iterable.

**Подробно.** Массив — iterable: каждый обход создаёт свежий итератор. Сам итератор (и генератор) одноразовый: второй обход пуст. При досрочном выходе потребитель вызывает `return()`, при естественном окончании (`done: true`) — нет ([P1](#p1-break-и-деструктуризация)).

**Ограничения.** Объект может быть итерируемым только «наполовину»: без `return()` очистка при `break` невозможна.

**Уточняющие вопросы.**
- *«Почему `const [a, b] = iterable` вызывает `return()`?»* — деструктуризация взяла два элемента и завершила обход досрочно.
- *«Чем `Object.keys(obj)` отличается от итерации?»* — обычный объект не iterable. `for…of` по нему — `TypeError`, нужен `Object.entries`.

</details>

### M2. Что такое генератор и зачем он backend-разработчику?

<details>
<summary>Ответ</summary>

**Тезис.** Генератор — функция `function*`, которая при вызове возвращает итератор и выполняет тело порциями до каждого `yield`. Значения вычисляются лениво, только когда потребитель вызывает `next()`.

**Подробно.** Применение в backend:
- обход курсора или постраничного API без загрузки всего в память;
- конвейеры обработки (`map` / `filter` / `take` из iterator helpers);
- явная очистка в `finally`, который выполнится при `break` потребителя.

Для ввода-вывода — асинхронный генератор `async function*` и `for await`.

**Ограничения.** Синхронный генератор с тяжёлой работой на каждом шаге блокирует event loop так же, как цикл.

**Уточняющий вопрос.** *«Что происходит при вызове `gen()`?»* — создаётся приостановленный контекст. Тело не выполняется до первого `next()` ([P2](#p2-генератор-и-finally)).

</details>

### M3. Зачем нужен Symbol и что такое well-known symbols?

<details>
<summary>Ответ</summary>

**Тезис.** Symbol — примитив с уникальной идентичностью. Он нужен для ключей свойств, которые не конфликтуют с другими именами и не видны в `Object.keys` и JSON. Well-known symbols — встроенные символы, через которые объект участвует в протоколах языка.

**Подробно.** `Symbol.iterator` и `Symbol.asyncIterator` — итерация, `Symbol.toPrimitive` — преобразование в примитив, `Symbol.hasInstance` — `instanceof`, `Symbol.toStringTag` — `Object.prototype.toString`, `Symbol.dispose` — освобождение ресурсов. `Symbol.for('k')` берёт символ из глобального реестра: один и тот же для всех модулей.

**Ограничения.** Symbol не даёт приватности: `Object.getOwnPropertySymbols` и `Reflect.ownKeys` его видят. Для приватности — `#private` (1.3).

**Уточняющий вопрос.** *«Что будет с символьным полем после `JSON.stringify` и `{ ...obj }`?»* — JSON его пропустит. Spread объекта копирует собственные перечисляемые свойства, включая символьные. Копирование через `Object.keys` его потеряет.

</details>

### M4. Как работает нестрогое равенство и почему '0' == false истинно, а '0' истинна?

<details>
<summary>Ответ</summary>

**Тезис.** `==` выполняет IsLooselyEqual: boolean приводится к числу (`false → 0`), строка — к числу (`'0' → 0`), и `0 == 0`. В условии `if ('0')` работает другое преобразование — ToBoolean, а любая непустая строка истинна.

**Подробно.** Ключевые правила `==`:
- `null == undefined`, и они не равны ничему другому;
- число и строка — строка к числу;
- boolean — к числу;
- объект и примитив — ToPrimitive объекта;
- `NaN` не равен ничему.

Отсюда `'' == 0`, `' \t' == 0`, `null >= 0` при `null == 0` — `false` ([P4](#p4-параметры-запроса), [P9](#p9-нестрогое-равенство)).

**Ограничения.** Это следствие алгоритмов спецификации, а не «случайность». Тем не менее в коде используют `===`, а параметры на границе разбирают явно.

**Уточняющий вопрос.** *«Почему `query.active == false` для `'false'` — `false`?»* — `'false'` приводится к числу `NaN`, а `NaN` не равен `0`. При этом `Boolean('false')` — `true`.

</details>

### M5. Почему 0.1 + 0.2 !== 0.3 и что с этим делать в деньгах?

<details>
<summary>Ответ</summary>

**Тезис.** Number — двоичное число с плавающей точкой IEEE 754. Дроби 0,1 и 0,2 в двоичной системе бесконечны и хранятся с округлением, сумма даёт `0.30000000000000004`. Так ведёт себя `double` в большинстве языков.

**Подробно.** Для сравнения дробей — допуск (`Math.abs(a - b) < Number.EPSILON` для малых чисел). Для денег допуск не подходит:
- хранить целые минимальные единицы (центы);
- или десятичное представление (`numeric` в базе, строка в API);
- явно выбирать правило округления;
- форматировать через `Intl.NumberFormat`.

**Ограничения.** `toFixed(2)` округляет двоичное значение: `(1.005).toFixed(2)` — `'1.00'`.

**Уточняющий вопрос.** *«Почему не хранить в Number центы всегда?»* — подходит, пока сумма меньше 2⁵³ минимальных единиц. Для валют с малыми единицами или очень больших сумм нужен BigInt или десятичный тип.

</details>

## Вопросы уровня Strong Middle

### SM6. Как генератор освобождает ресурс при раннем выходе из цикла?

<details>
<summary>Ответ</summary>

**Тезис.** `break`, `return` или исключение в теле `for…of` вызывают `iterator.return()`. Для генератора это возобновление в точке `yield` как `return`: выполняются блоки `finally`. Туда и ставят закрытие курсора или соединения.

**Подробно.** Если генератор обходят вручную через `next()` и бросают на полпути, `return()` никто не вызовет, и `finally` не выполнится вообще: сборщик мусора может собрать приостановленный генератор, но код генератора при этом не выполняет. Ручной обход оборачивают в `try` / `finally` с явным `it.return()`.

**Ограничения.** `yield` внутри `finally` приостанавливает генератор повторно: `return()` вернёт `{ done: false }`, и очистка не завершится без ещё одного `next()` (theory 7.1).

**Уточняющий вопрос.** *«Что будет, если тот же генератор обойти вторым `for…of` после `break` в первом?»* — генератор уже завершён `return()`, второй цикл не выполнит ни одной итерации.

</details>

### SM7. Как обработать большой поток данных асинхронной итерацией и где тут backpressure?

<details>
<summary>Ответ</summary>

**Тезис.** `for await (const chunk of readable)` читает следующую порцию только после окончания тела цикла. Пока обработка идёт, поток не читает дальше, его внутренний буфер заполняется, и источник притормаживается. Это и есть backpressure. `break` или исключение уничтожают поток и освобождают ресурс.

**Подробно.** Так же работает асинхронный генератор поверх курсора базы или постраничного API: следующий запрос уходит, когда потребитель готов. `events.on(emitter, name, { signal })` даёт async iterator событий. Но события, пришедшие во время обработки, буферизуются, а не тормозят источник. Притормозить его можно опцией `highWaterMark`, и только у emitter, который реализует `pause()` / `resume()` (документация Node.js v22, опция поддерживается с v20.0.0).

**Ограничения.** Последовательная обработка медленнее параллельной. Если элементы независимы, параллелизм вводят явно и ограниченно (3.3). Буферы, `highWaterMark` и `pipeline` — 3.4.

**Уточняющий вопрос.** *«Чем `for await` по потоку лучше `stream.on('data')`?»* — `data` не ждёт обработки и при медленном потребителе копит данные в памяти. `for await` ждёт тело и закрывает поток при выходе.

</details>

### SM8. Почему for await по массиву промисов может уронить процесс?

<details>
<summary>Ответ</summary>

**Тезис.** Массив — синхронный iterable уже запущенных промисов, а `for await` ждёт их по одному. Обработчик ко второму Promise подключается только после первого. Если второй отклонился раньше, в момент проверки у него нет обработчика: необработанное отклонение, и Node.js ≥ 15 завершает процесс.

**Подробно.** `for await (const v of [sleep(100), fail(10)])` — процесс завершился с кодом 1, `catch` вокруг цикла не сработал (проверено). Это та же ловушка, что и Promise, запущенный заранее (1.4). Для набора запущенных операций — `Promise.all` / `allSettled`, которые подписываются на все сразу.

**Ограничения.** `for await` по настоящему async iterable (генератор, поток) безопасен: следующая операция начинается только по запросу.

**Уточняющий вопрос.** *«Как обработать результаты по мере готовности?»* — подписать каждый Promise на обработчик сразу (например, `p.then(handle, handleError)`) и дождаться всех через `allSettled`.

</details>

### SM9. Как объект превращается в примитив и что такое подсказка?

<details>
<summary>Ответ</summary>

**Тезис.** Операция ToPrimitive передаёт подсказку: `"number"` для арифметики и сравнений, `"string"` для шаблонных строк и `String()`, `"default"` для бинарного `+` и `==`. Если у объекта есть `Symbol.toPrimitive`, вызывается он с подсказкой. Иначе — `valueOf` и `toString`: для `"string"` сначала `toString`, для остальных сначала `valueOf`.

**Подробно.** У `Date` подсказка `"default"` трактуется как `"string"`, поэтому `date + 1` — конкатенация, а `date - 0` — число. Объект, у которого `valueOf` возвращает число, ведёт себя в `+` как число ([P5](#p5-toprimitive)).

**Ограничения.** Если ни один метод не вернул примитив — `TypeError`.

**Уточняющий вопрос.** *«Где это встречается в backend?»* — классы денег и единиц измерения с `Symbol.toPrimitive` или `valueOf`. Это удобно, но неявное приведение в `+` и шаблонных строках даёт разные результаты, поэтому лучше явные методы (`toCents()`, `format()`).

</details>

### SM10. Как передавать идентификаторы bigint из базы через JSON?

<details>
<summary>Ответ</summary>

**Тезис.** Строками на всём пути: из драйвера, внутри сервиса и в API. Number теряет точность после 2⁵³ − 1 молча, BigInt роняет `JSON.stringify`.

**Подробно.**
- `pg` по умолчанию возвращает `int8` строкой именно поэтому (документация `pg-types`, проверено на `pg` 8.23.1).
- Глобальный парсер `parseInt` для `int8` превращает 9007199254740993 в 9007199254740992 — другой id.
- Парсер `BigInt` даёт точное значение, но `JSON.stringify` бросает `TypeError: Do not know how to serialize a BigInt`.

Если внутри нужна арифметика — BigInt внутри и явное преобразование в строку на границе (`toJSON` у DTO или `replacer`).

**Ограничения.** С ES2026 есть способ передать число без кавычек и без потерь: `replacer` возвращает `JSON.rawJSON(id.toString())`, а клиент разбирает ответ `reviver`, который читает `context.source` и делает `BigInt` (в Node.js v22.22.2 оба механизма работают, проверено запуском). Но это требует согласованного кода на обеих сторонах: стандартный `JSON.parse` без такого `reviver`, старые среды и многие JSON-библиотеки других языков число округлят. Поэтому строка остаётся самым переносимым форматом контракта.

**Уточняющий вопрос.** *«Почему не `BigInt.prototype.toJSON = …`?»* — это глобальная правка встроенного прототипа: она влияет на все библиотеки процесса и скрывает места, где BigInt попадает в ответ случайно.

</details>

### SM11. Когда уместны WeakMap и WeakRef и почему на них нельзя строить освобождение ресурсов?

<details>
<summary>Ответ</summary>

**Тезис.** `WeakMap` — для данных, привязанных к времени жизни объекта-ключа: метаданные, кеш вычислений по объекту. Запись исчезает вместе с ключом. `WeakRef` — для необязательного кеша, который можно пересоздать. Освобождение ресурсов на них не строят: спецификация не гарантирует ни сборку объекта, ни вызов колбэка FinalizationRegistry.

**Подробно.**
- Ключ `WeakMap` — объект или незарегистрированный символ. Строка или `Symbol.for` — `TypeError`.
- Перебора и `size` нет: иначе результат зависел бы от сборщика мусора.
- Колбэк FinalizationRegistry не вызывается при завершении процесса (проверено) и может не вызваться, если сборка не понадобилась.

Соединения, файлы, блокировки освобождают явно: `try` / `finally`, `onModuleDestroy`, `using` там, где он доступен.

**Ограничения.** Внутри одной задачи `deref()` всегда возвращает объект: он держится в `[[KeptAlive]]` до конца синхронного выполнения.

**Уточняющий вопрос.** *«Можно ли использовать FinalizationRegistry вообще?»* — как страховку для диагностики («ресурс не закрыт явно — залогировать»), но не как основной механизм.

</details>

### SM12. Что теряется при JSON.stringify и чем structuredClone отличается от JSON.parse(JSON.stringify())?

<details>
<summary>Ответ</summary>

**Тезис.** JSON:
- `Date` превращает в строку, обратно не восстанавливает;
- `Map` и `Set` — в `{}`;
- пропускает `undefined`, функции и символы в объектах, а в массивах заменяет их на `null`;
- `NaN` и `Infinity` пишет как `null`;
- теряет прототипы;
- падает на BigInt и циклах.

`structuredClone` сохраняет `Date`, `Map`, `Set`, `BigInt`, `RegExp`, ошибки и циклы, но не копирует функции (`DataCloneError`) и не сохраняет прототипы классов.

**Подробно.** `JSON.parse(JSON.stringify(x))` — не глубокая копия, а сериализация с потерями. Для копии внутри процесса — `structuredClone`. Для обмена между сервисами — JSON-совместимый контракт: даты ISO-строками, id и деньги строками, `toJSON` и `reviver` для своих типов ([P8](#p8-json-на-границе)).

**Ограничения.** `structuredClone` — функция хоста (стандарт HTML), а не ECMAScript. В Node.js она использует тот же механизм сериализации V8, что и сообщения между Worker Threads.

**Уточняющий вопрос.** *«Почему данные из Redis "потеряли методы"?»* — после `JSON.parse` это обычные объекты. Экземпляры классов восстанавливают явно (`plainToInstance`, фабрики DTO).

</details>

## Вопросы уровня Senior

### S13. Как устроен IteratorClose и что происходит при ошибках в return()?

<details>
<summary>Ответ</summary>

**Тезис.** При досрочном выходе потребитель вызывает `iterator.return()`. Если выход вызван исключением, а `return()` тоже бросил, наружу уходит исходное исключение. Если выход нормальный (`break`), а `return()` бросил или вернул не объект, — его ошибка или `TypeError`.

**Подробно.** Это защищает от потери первопричины: ошибка очистки не затирает ошибку обработки. У генератора `return(v)` выполняет `finally` в точке `yield`. `yield` внутри `finally` снова приостанавливает генератор. Для async-итераторов AsyncIteratorClose ждёт Promise из `return()`, поэтому `break` из `for await` по потоку дожидается его уничтожения.

**Ограничения.** Если у итератора нет `return()`, закрывать нечего, и ресурс освобождается только при естественном окончании.

**Уточняющий вопрос.** *«Как написать курсор, который гарантированно закрывается?»* — асинхронный генератор с `try` / `finally` и закрытием в `finally`. Потребителю — только `for await`, без ручного `next()` или с явным `return()` в `finally`.

</details>

### S14. Что спецификация гарантирует о WeakRef и FinalizationRegistry?

<details>
<summary>Ответ</summary>

**Тезис.**
- Почти ничего о сборке: «This specification does not make any guarantees that any object or symbol will be garbage collected».
- Колбэк FinalizationRegistry «may eventually be made».
- Гарантирует она другое: цель `WeakRef` остаётся живой до конца текущего синхронного выполнения после `new WeakRef` или `deref()` (`[[KeptAlive]]`).
- И определяет, что может быть слабым ключом: CanBeHeldWeakly — объект или незарегистрированный символ (символы — с ES2023).

**Подробно.**
- Liveness неразрешима, движки используют достижимость.
- Оптимизации вроде удаления неиспользуемых переменных разрешены и могут «досрочно» опустошить WeakRef.
- Порядок и момент колбэков очистки не определены (job очистки — без требований к порядку, 1.5).

Поэтому логика не может зависеть от того, собран ли объект.

**Ограничения.** Эксперименты с `--expose-gc` показывают поведение конкретной версии V8, а не язык (урок 1.2, раздел 7.6).

**Уточняющий вопрос.** *«Почему у WeakMap нет `size`?»* — его значение зависело бы от момента сборки мусора, и программа стала бы недетерминированной.

</details>

### S15. Что такое explicit resource management и как писать код сейчас?

<details>
<summary>Ответ</summary>

**Тезис.** Объявления `using` / `await using` вызывают `[Symbol.dispose]()` / `[Symbol.asyncDispose]()` при выходе из блока в обратном порядке — детерминированная замена `try` / `finally`. `DisposableStack` собирает несколько ресурсов. На 2026-10-12 это есть в рабочем черновике ECMAScript 2027, но не в опубликованной редакции ES2026.

**Подробно.** В Node.js v22.22.2 `Symbol.dispose` и `Symbol.asyncDispose` определены, `FileHandle` имеет `[Symbol.asyncDispose]()` (Experimental, с v20.4.0), но синтаксиса `using` нет: `SyntaxError`. Поэтому сейчас:
- освобождение — `try` / `finally` и lifecycle hooks;
- у своих классов-ресурсов можно уже определять `[Symbol.asyncDispose]`, чтобы перейти на `using`, когда его поддержит версия Node.js или компилятор.

**Ограничения.** TypeScript умеет компилировать `using` для сред без нативной поддержки: TypeScript 7.0.2 с `--target es2022` вывел хелперы `__addDisposableResource` / `__disposeResources`, и результат на Node.js v22.22.2 вызвал `[Symbol.dispose]()` при выходе из функции (проверено запуском). Поддержку и нужные полифилы (`Symbol.dispose`) сверять с версией компилятора.

**Уточняющий вопрос.** *«Почему это лучше FinalizationRegistry?»* — момент освобождения детерминирован и привязан к выходу из блока, а не к сборке мусора.

</details>

### S16. Как спроектировать контракт API для дат, денег и идентификаторов?

<details>
<summary>Ответ</summary>

**Тезис.** Только JSON-совместимые типы с однозначным разбором:
- даты — ISO 8601 в UTC (`2026-01-02T00:00:00.000Z`);
- деньги — строка с фиксированной точностью или целое в минимальных единицах плюс код валюты;
- идентификаторы `bigint` — строки.

Всё это фиксируется в схеме (OpenAPI) и проверяется на входе и выходе.

**Подробно.**
- `Date` при сериализации становится строкой автоматически, но обратно не восстанавливается: DTO на входе явно разбирает строку.
- Деньги в Number ломаются на округлении.
- `bigint` в Number — на точности.
- `undefined` и `null` различаются только если контракт это определяет: JSON пропускает `undefined`.

**Ограничения.** Клиенты на разных языках разбирают числа по-разному: большие целые теряют точность в стандартном `JSON.parse` JavaScript (без `reviver` с `context.source`, ES2026) и в части JSON-библиотек других языков. Строки однозначны везде.

**Уточняющий вопрос.** *«Как не забыть преобразование на границе?»* — DTO с `toJSON` или сериализатором ответа (interceptor в NestJS, урок 7.5) и тесты с граничными значениями: id больше 2⁵³, сумма с половиной минимальной единицы, дата на границе суток.

</details>

## Предскажи результат

Каждый фрагмент — отдельный файл `.cjs`. Запишите точный вывод и одну-две фразы о механизме, затем раскройте ответ. P1–P8 — обязательная часть, P9–P11 опираются на углубление.

### P1. break и деструктуризация

```js
const log = [];
const src = {
  [Symbol.iterator]() {
    let i = 0;
    return { next: () => ({ value: ++i, done: i > 3 }), return: () => { log.push('closed'); return { done: true }; } };
  },
};
const [a, b] = src;
const all = [...src];
for (const x of src) { if (x === 3) break; }
console.log(a, b, all, log);
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `1 2 [ 1, 2, 3 ] [ 'closed', 'closed' ]`.

**Почему:** деструктуризация взяла два значения и закрыла итератор. Spread дошёл до `done: true` — `return()` не вызывается. `break` закрыл третий итератор. Каждое использование `src` создавало новый итератор, поэтому значения начинались с 1.

</details>

### P2. Генератор и finally

```js
function* cursor() {
  console.log('open');
  try { yield 1; yield 2; yield 3; }
  finally { console.log('close'); }
}
const c = cursor();
console.log('created');
console.log(c.next().value);
for (const v of c) { console.log('loop', v); break; }
console.log(c.next());
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `created`, `open`, `1`, `loop 2`, `close`, `{ value: undefined, done: true }`.

**Почему:** тело не выполняется до первого `next()`. `for…of` продолжает тот же генератор с места остановки. `break` вызывает `return()`, выполняется `finally`. После этого генератор завершён.

</details>

### P3. for await

```js
async function* rows() {
  try {
    for (let i = 1; i <= 5; i++) { await null; yield i; }
  } finally { console.log('release connection'); }
}
(async () => {
  let sum = 0;
  for await (const r of rows()) { sum += r; if (r === 2) break; }
  console.log('sum', sum);
})();
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `release connection`, `sum 3`.

**Почему:** `break` из `for await` вызывает `return()` асинхронного генератора и **ждёт** его завершения, включая `finally`. Только после этого выполняется код после цикла.

</details>

### P4. Параметры запроса

```js
const query = { page: '0', size: '', active: 'false' };
console.log(query.page == 0, query.page ? 'truthy' : 'falsy', query.size == 0, query.active == false, Boolean(query.active));
console.log(Number(query.size), parseInt(query.size, 10), Number('10abc'), parseInt('10abc', 10));
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `true truthy true false true`, затем `0 NaN NaN 10`.

**Почему:** `'0' == 0` приводит строку к числу. Непустая строка `'0'` истинна. `'' == 0`. `'false'` приводится к `NaN`, поэтому `!= false`, а `Boolean('false')` истинно. `Number('')` — `0`, `parseInt('')` — `NaN`. `parseInt` читает префикс, `Number` требует число целиком.

</details>

### P5. toPrimitive

```js
const temp = {
  celsius: 20,
  [Symbol.toPrimitive](hint) { return hint === 'string' ? `${this.celsius}°C` : this.celsius; },
};
console.log(`${temp}`, temp + 5, temp * 2, temp > 10, String(temp), [temp] + '');
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `20°C 25 40 true 20°C 20°C`.

**Почему:** шаблонная строка и `String()` дают подсказку `"string"`. Бинарный `+` — `"default"`, здесь возвращается число, и получается сложение. `*` и `>` — `"number"`. `[temp] + ''` преобразует массив в строку через `join`, и элемент приводится к строке с подсказкой `"string"`.

</details>

### P6. Числа

```js
const total = 0.1 * 3;
console.log(total, total === 0.3, (total).toFixed(2));
console.log(Number('9007199254740993'), BigInt('9007199254740993'), 2 ** 53 + 1 === 2 ** 53);
console.log(5n / 2n, typeof (5n * 2n), 0.1 * 3 * 100 | 0);
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `0.30000000000000004 false 0.30`, затем `9007199254740992 9007199254740993n true`, затем `2n bigint 30`.

**Почему:** двоичная плавающая точка. Number не различает целые после 2⁵³, а BigInt хранит значение точно. Деление BigInt целочисленное. `| 0` отбрасывает дробную часть `30.000000000000004`.

</details>

### P7. WeakMap и слабые ключи

```js
const wm = new WeakMap();
const tryKey = (k, label) => { try { wm.set(k, 1); console.log(label, 'ok'); } catch (e) { console.log(label, e.name); } };
tryKey({}, 'object');
tryKey(Symbol('local'), 'symbol');
tryKey(Symbol.for('global'), 'Symbol.for');
tryKey('id', 'string');
tryKey(Object(1n), 'boxed bigint');
console.log(typeof wm.size, typeof wm.keys);
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `object ok`, `symbol ok`, `Symbol.for TypeError`, `string TypeError`, `boxed bigint ok`, `undefined undefined`.

**Почему:** слабым ключом может быть объект (включая объект-обёртку над BigInt) или незарегистрированный символ (с ES2023). Символ из `Symbol.for` и примитивы — нет: их можно «воссоздать» без ссылки на оригинал. Размера и перебора у `WeakMap` нет.

</details>

### P8. JSON на границе

```js
class Money { constructor(c) { this.cents = c; } toJSON() { return { amount: (this.cents / 100).toFixed(2), currency: 'USD' }; } }
const payload = { at: new Date(Date.UTC(2026, 0, 2)), price: new Money(1050), tags: new Set(['x']), skip: undefined, arr: [undefined, NaN] };
```

<details>
<summary>Ответ и объяснение</summary>

**Почему:** `Date` и `Money` сериализованы через `toJSON`. `Set` стал `{}`. `undefined` в объекте пропущен, в массиве стал `null`, как и `NaN`. После разбора — строки и обычные объекты: ни `Date`, ни `Money`.

</details>

### P9. Нестрогое равенство

```js
console.log(null == 0, null >= 0, undefined == null, '' == 0, ' \t' == 0, [1] == 1, [1, 2] == '1,2', {} == '[object Object]');
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `false true true true true true true true`.

**Почему:** `null` в `==` равен только `undefined`, но в `>=` приводится к `0`. Строка из пробельных символов приводится к `0`. Массивы и объекты приводятся к примитиву через `toString`: `'1'`, `'1,2'`, `'[object Object]'`.

</details>

### P10. Ленивые iterator helpers

```js
let produced = 0;
function* numbers() { while (true) { produced++; yield produced; } }

```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `[ 2, 4, 6 ] produced 6`.

**Почему:** iterator helpers (ES2025, есть в Node.js 22) ленивые: `take(3)` перестаёт запрашивать значения после третьего подходящего, и генератор произвёл ровно шесть чисел. Бесконечный генератор не мешает.

</details>

### P11. SameValueZero в Map и Set

```js
const m = new Map([[NaN, 'nan'], [0, 'zero']]);
const s = new Set([-0, 0, NaN, NaN]);
console.log(m.get(NaN), m.get(-0), s.size, [-0].includes(0), Object.is([-0][0], 0));
```

<details>
<summary>Ответ и объяснение</summary>

**Ответ:** `nan zero 2 true false`.

**Почему:** ключи `Map`, элементы `Set` и `includes` сравниваются по SameValueZero: `NaN` равен себе, `-0` равен `0`. `Object.is` (SameValue) различает `-0` и `0`.

</details>

## Задачи на выбор решения

Формат: условия → варианты → выбор → при каких условиях выбор перестаёт быть верным.

### В1. Экспорт большой выборки в CSV

**Условия.** Эндпоинт отдаёт CSV по заказам за период: до 5 млн строк, около 200 байт на строку. Лимит памяти контейнера — 512 МБ, одновременно до 5 экспортов.

**Варианты:** загрузить всё в массив и сформировать строку; асинхронный генератор поверх курсора базы и запись в ответ; поток (`Readable` из генератора) с `pipeline` в ответ.

<details>
<summary>Разбор</summary>

**Выбор.** Асинхронный генератор, который читает курсор порциями, обёрнутый в `Readable.from` и отправленный через `pipeline(source, transformToCsv, res)`. Память ограничена порцией и буферами потоков. Backpressure замедляет чтение из базы, если клиент медленный. При обрыве клиента `pipeline` уничтожает цепочку, генератор получает `return()`, и курсор закрывается в `finally`.

**Почему не массив.** 5 млн × 200 байт — около 1 ГБ только на строки, плюс объекты строк из драйвера. Пять одновременных экспортов не помещаются в 512 МБ даже теоретически.

**Почему не только `for await` с `res.write`.** Работает, но нужно вручную учитывать возврат `write()` и событие `drain`, иначе буфер ответа растёт при медленном клиенте. `pipeline` делает это сам (3.4).

**Когда выбор перестаёт быть верным.**
- Выборка маленькая (тысячи строк) — массив проще и достаточно.
- Экспорт долгий (минуты) и должен переживать обрыв соединения — фоновая задача, файл в объектном хранилище и ссылка (10.2).

</details>

### В2. Тип денежных сумм в сервисе

**Условия.** Сервис биллинга: валюты с двумя знаками и одна с тремя (KWD), налоги считаются процентом с округлением, отчёты агрегируют миллионы операций. База — PostgreSQL.

**Варианты:** Number с дробной частью; целые минимальные единицы в Number; BigInt минимальных единиц; `numeric` в базе и десятичная библиотека в приложении.

<details>
<summary>Разбор</summary>

**Выбор.** `numeric` в базе для хранения и агрегатов (суммы в SQL точные) и целые минимальные единицы в приложении с явной точностью валюты. Number допустим, пока суммы меньше 2⁵³ минимальных единиц, иначе BigInt. Округление налога — одна функция с явным правилом, применяется в одном месте. В API — строка с фиксированной точностью плюс код валюты.

**Почему не Number с дробной частью.** Ошибки двоичного представления накапливаются в агрегатах и всплывают на округлении (`(1.005).toFixed(2)`).

**Почему не только десятичная библиотека.** Подходит, если много процентной арифметики. Цена — производительность и необходимость конвертировать на каждой границе. Целые минимальные единицы проще для типичных операций сложения и умножения на целое количество.

**Когда выбор перестаёт быть верным.**
- Нужны дробные минимальные единицы (тарифы за мегабайт, курсы валют с 6–8 знаками) — десятичная арифметика с явной точностью везде.
- Суммы выходят за 2⁵³ минимальных единиц (криптовалюты с 18 знаками) — BigInt или десятичная библиотека, Number не годится вовсе.

</details>

## Как отличить поверхностный ответ от сильного

| Тема | Поверхностный ответ | Сильный ответ |
|---|---|---|
| Итераторы | «`for…of` перебирает массив» | объясняет протокол, одноразовость итератора, `return()` и закрытие ресурса |
| Генераторы | «функция со звёздочкой» | ленивость, приостановленный контекст, `finally` при `break`, асинхронный вариант для ввода-вывода |
| Асинхронная итерация | «`for await` для промисов» | backpressure, закрытие потока, ловушка с массивом промисов |
| Приведение | «`==` непредсказуем» | выводит результат из IsLooselyEqual и ToPrimitive; разбирает параметры явно |
| Числа | «используйте `toFixed`» | IEEE 754, `MAX_SAFE_INTEGER`, минимальные единицы, строки для id, BigInt и JSON |
| Слабые ссылки | «WeakMap сам чистится» | ключи, отсутствие перебора, `[[KeptAlive]]`, отсутствие гарантий сборки, явное освобождение ресурсов |
| Сериализация | «`JSON.parse(JSON.stringify())` — копия» | перечисляет потери, сравнивает со `structuredClone`, проектирует JSON-совместимый контракт |
