## Ключевая формулировка урока

**Параллельно в Node.js работают только ядро ОС, пул потоков libuv, Worker Threads и процессы. Пул — 4 потока на весь процесс, общий для `fs`, `dns.lookup`, `crypto`, `zlib` и всех Worker; когда он занят, операции ждут при свободном event loop, и задержка цикла этого не показывает. Worker Thread — отдельный isolate для CPU-работы: он освобождает основной поток, но не ускоряет вычисление и стоит запуска и копирования данных. Процессы (`cluster`, реплики) используют ядра, но не делят память. Ограничение concurrency защищает ёмкость зависимости, rate limiting — квоту, и оба умножаются на число инстансов.**

## Как проверялись примеры

Каждый пример с выводом запущен на **Node.js v22.22.2** (libuv 1.51.0, Windows 10 x64, AMD Ryzen 5 3600X: 6 ядер, 12 потоков) как файл `.cjs`. Чтение `UV_THREADPOOL_SIZE` из кода повторено на **v18.20.8**, **v24.22.0** и **v26.12.0**; причина различия найдена в исходниках libuv 1.51.0 и 1.52.1. Время — одного запуска, при повторах отличалось на 5–25 %; выводы опираются на соотношения. Утверждения о Linux проверены в Docker (Linux, cgroup v2) на образах `node:18.20.8-slim`, `node:22.22.2-slim` и `node:24.22.0-slim`: присваивание `UV_THREADPOOL_SIZE` из кода и `os.availableParallelism()` при `--cpus=2`; io_uring — только по документации libuv. Поведение API сверено с документацией Node.js latest-v22.x, руководством «Don't Block the Event Loop», документацией libuv v1.x, PM2 и BullMQ, модель памяти — с черновиком ECMAScript на tc39.es — 2026-10-15.
