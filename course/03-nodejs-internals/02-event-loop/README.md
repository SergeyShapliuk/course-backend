## Ключевая формулировка урока

**Event loop — цикл libuv, который проходит фазы timers, pending, poll, check и close и спит в poll, когда делать нечего. Между любыми двумя колбэками Node.js опустошает сначала очередь `process.nextTick`, затем очередь микрозадач V8. Гарантированы только немногие правила порядка: `nextTick` раньше промисов внутри колбэков, `setImmediate` раньше таймера внутри колбэка ввода-вывода, FIFO внутри очереди. Порядок таймера и `setImmediate` в главном модуле случаен, а порядок `nextTick` и промисов на верхнем уровне модуля зависит от формата модуля и версии Node.js. Любой долгий колбэк останавливает цикл для всех запросов, и это измеряют задержкой цикла, а не временем ответа отдельного эндпоинта.**

## Как проверялись примеры

Каждый пример с выводом запущен на **Node.js v22.22.2** (libuv 1.51.0, Windows 10 x64): CommonJS — как `.cjs`, ESM — как `.mjs`. Выполнение очередей после каждого колбэка сравнено с **v10.24.1**; порядок в ESM повторён на **v18.20.8** (libuv 1.44.2), **v24.22.0** и **v26.12.0**; пример из обсуждения libuv 1.45 — на v18.20.8 и v22.22.2. Примеры с недетерминированным порядком запускались многократно, частоты указаны в тексте. Сценарий с экспортом выполнен двумя процессами (сервер и клиент) дважды; числа — из одного запуска, второй отличался не более чем на 10 %. Значения задержки цикла зависят от платформы: на Windows гранулярность таймеров около 15,6 мс. Поведение сверено с исходниками Node.js v22.22.2 и libuv 1.44.2 / 1.51.0, документацией Node.js latest-v22.x и latest-v26.x, руководствами nodejs.org/en/learn, документацией libuv v1.x, CHANGELOG_V11 и CHANGELOG_V26 — 2026-10-15.
